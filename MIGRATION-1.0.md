# 1.0.0 migration

The gateway API and Lunixi.Sdk dependency now require canonical minor-unit strings. Native nopCommerce decimal order totals are converted through invariant decimal text and the order currency exponent; native ledger columns retain exact signed 64-bit integers. Authenticated numeric money responses fail closed. The native coordinator resolves full capture/refund requests into an exact persisted amount before calling the SDK bridge. Capture/refund therefore require a positive canonical string at that bridge; null and zero are rejected before transport. Only void has no amount. The bridge does not convert null into a full-remaining SDK operation.

Default release builds restore `Lunixi.Sdk` from NuGet.org using the exact version in `Directory.Build.props` and committed package locks. Run `python3 scripts/bootstrap.py`, `python3 scripts/build.py --restore`, and `python3 scripts/verify-clean-restore.py` after that SDK version is available. Package-mode acceptance must regenerate locks from the actual published package once, then pass a clean locked restore; never invent a content hash or infer registry publication from a source tag.

For explicit development acceptance, `--sdk-source=/absolute/path/to/dotnet` selects a reviewed source project and its separate source-mode lock. `--sdk-package=/absolute/path/to/Lunixi.Sdk.<version>.nupkg` selects reviewed local package bytes and a separate local lock/cache; the direct MSBuild alternative is `UseLunixiSdkPackage=true` plus `LunixiSdkLocalFeed=/absolute/path/to/feed`. These development overrides do not satisfy the public registry release gate.

Existing attempts retain their original request, hash and operation key. Reconcile old uncertain attempts rather than rewriting persisted bytes or recharging. JPY/TRY/KWD use 0/2/3 decimal exponents; large exact fixture `9007199254740993` is preserved. The maximum fiat minor amount is `9223372036854775807`; actual provider and native platform constraints may be lower. Raw webhook signatures, ownership, approved totals and retry protections are unchanged.
